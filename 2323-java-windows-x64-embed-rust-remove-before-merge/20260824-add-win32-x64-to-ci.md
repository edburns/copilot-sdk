## Required architecture

### One publisher

There must be exactly one Maven deployment for each release or snapshot publication:

* The Windows job only builds, validates, checksums, and uploads the `win32-x64` classifier JAR as a GitHub Actions artifact.
* The Ubuntu deployment job builds the `linux-x64` classifier, downloads and verifies the Windows artifact, attaches it to the `copilot-native` Maven project, and performs the single deploy.
* The single deploy must contain the primary placeholder runtime JAR, POM, sources, Javadoc, `linux-x64`, and `win32-x64`.
* For releases, the normal release signing lifecycle must sign every deployed artifact, including both classifier JARs.
* Never publish a partial platform set and never publish from Windows.

### Immutable source identity

Both classifier builds in one publication must use identical source:

* Releases: Windows and Ubuntu must check out the exact generated `java/v<release-version>` tag.
* Snapshots: both jobs must check out the same explicit commit SHA. Pass it through job outputs rather than relying on mutable branch state or an implicit checkout.
* Include source identity and artifact SHA-256 details in job summaries so a publication can be audited.
